### **STEP 2: Configure Railway (Backend)**

#### **A. Verify Environment Variables**

1. Go to **Railway Dashboard** → Your **Backend Service**
2. Click **Variables** tab
3. Make sure these exist:

```
DATABASE_URL=postgresql://user:pass@host:port/db  (auto-generated by Railway Postgres)
ENVIRONMENT=production
DEBUG=false
PORT=8000  (Railway sets this automatically, but you can verify)
```

#### **B. Get Your Backend URL**

1. In Railway → Your **Backend Service** → **Settings**
2. Find **Domains** section
3. Copy your Railway URL (e.g., `https://backend-production-xxxx.up.railway.app`)
4. **SAVE THIS URL - YOU'LL NEED IT FOR FRONTEND!**

#### **C. Update CORS Origins**

1. Still in **Variables** tab
2. Find or add `CORS_ORIGINS`
3. Set it to:
```
CORS_ORIGINS=https://your-vercel-app.vercel.app,http://localhost:5173,http://localhost:3000
```
*Replace `your-vercel-app.vercel.app` with your actual Vercel domain*

#### **D. Railway Build Settings**

1. Go to **Settings** → **Build**
2. Configure:
   - **Builder:** `Nixpacks`
   - **Root Directory:** `backend`
   - **Metal Build Environment:** Toggle **ON** ⚡
   - **Dockerfile Path:** Leave **empty** or delete
   - **Build Command:** Leave **empty**
   - **Start Command:** `uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}`

3. **Save** and **Deploy**

---

### **STEP 3: Configure Vercel (Frontend)**

#### **A. Set Environment Variable in Vercel**

1. Go to **Vercel Dashboard** → Your **Frontend Project**
2. Click **Settings** → **Environment Variables**
3. Add this variable:

| Name | Value | Environment |
|------|-------|-------------|
| `VITE_API_URL` | `https://backend-production-xxxx.up.railway.app/api` | Production |

**⚠️ IMPORTANT:** Replace `backend-production-xxxx.up.railway.app` with your **actual Railway backend URL** from Step 2B!

4. Click **Save**

#### **B. Redeploy Frontend**

1. In Vercel Dashboard → **Deployments**
2. Click **...** (three dots) on latest deployment
3. Click **Redeploy**
4. Check **"Use existing Build Cache"** 
5. Click **Redeploy**

**OR** push a small change to trigger redeployment:

```bash
# Make a small change
git commit --allow-empty -m "Trigger Vercel redeploy with backend URL"
git push origin main
```

## 🔍 Troubleshooting

### **Issue 1: Still Getting PORT Errors in Railway**

**Solution:**
1. Make sure you pushed the latest changes
2. In Railway → Settings → scroll to bottom
3. Click **"Restart Deployment"**
4. Check if `${PORT:-8000}` is in the start command (not `$PORT`)

---

### **Issue 2: Frontend Shows "Failed to Fetch"**

**Possible Causes & Fixes:**

#### **A. Wrong Backend URL**
- Check Vercel environment variable `VITE_API_URL`
- Should be: `https://your-backend-url.railway.app/api` (with `/api` at the end!)
- Redeploy frontend after changing

#### **B. CORS Issue**
- Check Railway backend variable `CORS_ORIGINS`
- Should include your Vercel domain
- Example: `https://strategy-builder.vercel.app,http://localhost:5173`

#### **C. Backend Not Running**
- Go to Railway → Backend Service → check status
- Should show **"Active"** with green dot
- If crashed, check logs for errors

---

### **Issue 3: Backend Deploys but Crashes**

**Check Logs For:**

1. **Database Connection Error:**
   ```
   Could not connect to database
   ```
   **Fix:** Verify `DATABASE_URL` in Railway variables

2. **Import Error:**
   ```
   ModuleNotFoundError: No module named 'x'
   ```
   **Fix:** Check `requirements.txt` has all dependencies

3. **Port Already in Use:**
   ```
   Address already in use
   ```
   **Fix:** This shouldn't happen on Railway. Restart deployment.

## 🎯 What Changed to Fix the Issues

### **Backend PORT Error Fix:**

**Before:**
```bash
uvicorn app.main:app --host 0.0.0.0 --port $PORT
```
❌ This treats `$PORT` as a literal string

**After:**
```bash
uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
```
✅ This properly expands the PORT environment variable with fallback to 8000

### **Frontend Connection Fix:**

**Before:**
- No environment variable set in Vercel
- Frontend defaulting to `http://localhost:8000/api`
- Can't connect to Railway backend

**After:**
- `VITE_API_URL` set to Railway backend URL in Vercel
- Frontend correctly points to production backend
- CORS properly configured to allow Vercel domain
